# AI 回答质量基线

当前状态：24 道固定问题、离线知识就绪度评测和回答报告评分器已经建立。2026-09-19 已完成转专业官方知识修复前后的离线对照，并在明确授权后完成真实知识导入、向量生成和 24 道真实回答基线。

## 评测内容

固定评测集位于 `quality/ai-answer-quality-cases.json`，共 24 道公开校园问题：

- 6 道年度时间题；
- 6 道资格条件题；
- 4 道材料和流程题；
- 4 道多意图题；
- 2 道历史参考题；
- 2 道资料不足、应克制回答的题。

每道题记录预期来源、必须覆盖的答案点和禁止出现的过时或无依据表述。评测集不含学号、手机号等个人信息。

## 离线运行

```powershell
node .\scripts\test_ai_quality_baseline.mjs
node .\scripts\benchmark_ai_quality.mjs
```

需要保存报告时，把报告写入已被 Git 忽略的 `out/ai-quality/`：

```powershell
node .\scripts\benchmark_ai_quality.mjs --output .\out\ai-quality\local-report.json
```

离线模式不会连接 Supabase、模型或学校网站。它检查前 5 条关键词检索结果是否包含预期来源，以及召回资料是否覆盖人工标注的关键事实。两道“无依据克制”题需要观察实际回答，因此不计入离线知识就绪度的 22 道可评估题。

## 2026-09-19 对照结果

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 正确来源进入前 5 条 | 63.6% | 100.0% |
| 来源组覆盖率 | 58.3% | 100.0% |
| 召回资料关键点覆盖率 | 62.1% | 93.9% |

修复后仍缺少的 6.1% 都来自两道历史参考题。知识库已经具备 2026 年参考资料，但服务端尚未实现“当前年度缺失时才使用往年通知，并强制标注年份和仅供参考”的阶段 C 规则。此缺口保留为下一阶段的可验证目标。

本地原始报告为 `out/ai-quality/before-knowledge-fix.json` 和 `out/ai-quality/after-knowledge-fix-v2.json`，不会提交到 Git。

## 2026-09-19 真实基线

两篇转专业官方资料已写入真实 Supabase：人工知识导入结果为新增 2、更新 0、未变化 17；知识文档总数变为 62，知识切片总数为 63。两篇新资料共生成 3 个向量。

24 道真实模型回答使用同一个匿名测试标识，分两个每小时额度窗口完成，没有通过更换标识绕过额度。最终结果：

| 指标 | 结果 |
|---|---:|
| 完整通过 | 19/24（79.2%） |
| 答案关键点覆盖 | 85.3% |
| 引用率 | 100.0% |
| 历史资料正确标注 | 0/2（0.0%） |
| 无依据克制 | 2/2（100.0%） |
| 禁用表述命中 | 0 |
| 完整响应中位数 | 6.303 秒 |
| 完整响应 P95 | 10.768 秒 |
| 平均回答长度 | 592 字符 |

24 个成功回答均使用 Responses API，且思考模式为关闭。完整运行共记录 27 次尝试：24 次成功、1 次按额度规则停止、2 次客户端连接失败；连接失败没有模型回答，不计入质量和耗时样本。

未完整通过的 5 题为 `condition-01`、`process-01`、`multi-01`、`history-01` 和 `history-02`。前三题说明长政策的单切片召回会遗漏前半段的适用年级和基本条件；后两题说明服务端还没有统一强制“往年资料、仅供参考、不能确认下一年度”的提示。下一步应先修复这两类问题，再用同一评测集复测。

本地真实报告为 `out/ai-quality/live-after-knowledge-fix.json`，评分明细为 `out/ai-quality/live-after-knowledge-fix-score.json`。报告记录了题集和官方知识文件的 SHA-256 校验值，均不会提交到 Git。

## M3 历史参考复测

2026-09-19 部署 v29 后，只复测 `history-01` 和 `history-02`。两题完整通过率、关键点覆盖率、引用率和历史标注率均为 100%。两题均由接口返回 `answerMode=historical_reference`，引用的 2026 年通知也带有历史参考、通知年份 2026 和目标年份 2027 标记。

两次完整响应分别为 9.755 秒和 6.156 秒。原始报告为 `out/ai-quality/m3-history-live-v29.json`，不会提交到 Git。该两题复测只证明 M3 已通过；24 题最终质量和速度仍在 M8 统一复测。

## M4 多意图检索验收

M4 已部署并完成线上验收。当前实现会识别时间、条件、材料、流程、地点和联系方式，组合年度通知与现行政策，并允许同一长文最多两个相关切片进入模型上下文。接口还会返回识别到的问题维度和服务端上海日期，来源记录保留实际切片数。

`scripts/test_multi_intent_retrieval.mjs` 使用仓库内两篇真实转专业官方资料验证：组合后的上下文包含 2026 年报名日期、大学一年级、已注册学籍、申请表、只能选择一个专业、笔试、面试和不少于 5 个工作日的公示期限。综合服务端模拟同时验证来源按文档去重、年度通知与政策均被保留、第三个切片不会进入上下文，以及历史参考、关键词降级、向量失败、限额和超时行为不退化。

首次部署后，`condition-01` 和 `process-01` 完整通过；`multi-01` 的检索与接口检查通过，但答案遗漏适用年级，只覆盖 3/4 个答案点。修正版要求条件回答先说明适用对象和年级，并在已识别明确主题时排除其他主题资料。v31 复测 `multi-01` 后覆盖 4/4 个答案点、引用率 100%，问题维度、服务端日期、来源去重和双切片检查全部通过，完整响应为 14.008 秒。三道 M4 目标题的最新结果为 3/3 通过，答案点覆盖率和引用率均为 100%，完整响应中位数 10.670 秒、P95 14.008 秒。汇总报告为 `out/ai-quality/m4-final-summary.json`，原始报告为 `out/ai-quality/m4-live.json` 和 `out/ai-quality/m4-multi-retest.json`。

M4 验收时还修正了一个评分误差：旧评分词组没有接受“每人限选 1 个专业”和“名单公示不少于 5 个工作日”这两种等价说法，导致 `process-01` 被误判失败。只扩充等价说法、不修改任何旧回答后，修改前真实基线由 19/24（79.2%）校准为 20/24（83.3%），答案关键点覆盖率由 85.3% 校准为 88.2%。剩余未通过的是 `condition-01`、`multi-01` 和两道历史参考题。后续 M8 前后对照应使用这份校准结果。

24 题最终质量和速度对照仍留到 M8。

## 真实回答评分

真实回答测试会消耗额度并产生脱敏用量日志，必须先取得明确授权。获得授权后，测试结果可以保存为本地 JSON：

```json
{
  "cases": [
    {
      "id": "annual-01",
      "answer": "回答正文",
      "sources": [{ "slug": "official-major-transfer-notice-2026" }]
    }
  ]
}
```

评分命令：

```powershell
node .\scripts\benchmark_ai_quality.mjs --responses .\out\ai-quality\answers.json --output .\out\ai-quality\answer-score.json
```

回答评分包括完整通过率、答案点覆盖率、引用率、历史资料标注率、无依据克制率和禁用表述命中数。评分报告只保存结果，不需要把模型答案提交进仓库。

已经获得真实测试授权时，可使用下面的可续跑入口。它从前端文件读取公开 key，不读取或保存高权限密钥；遇到每小时额度后停止，并在同一报告上续跑，不能通过更换匿名 ID 绕过额度。

```powershell
node .\scripts\run_ai_quality_live.mjs --live --client-id codex-quality-20260919 --output .\out\ai-quality\live-after-knowledge-fix.json
node .\scripts\run_ai_quality_live.mjs --live --resume --client-id codex-quality-20260919 --output .\out\ai-quality\live-after-knowledge-fix.json
```

需要同时完成真实知识导入、向量生成和首轮基线时，可运行 `scripts/publish_reviewed_knowledge.ps1`。它使用隐藏输入读取 Supabase Secret key 和百炼向量模型 key，任务结束后立即清除当前进程中的变量。
