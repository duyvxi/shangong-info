## 1. 结论

用户提出的四项建议都可行，但应按以下顺序实施：

1. 先建立回答质量基线。
2. 补齐当前官方资料并修正检索时效。
3. 约束模型直接回答时间、条件、材料和流程。
4. 安全渲染 Markdown。
5. 在完整响应基线不退步的前提下加入流式输出。

只改提示词不能解决当前问题。截图中的回答引用了《山东工商学院本（专）科学生转专业学习管理规定》，但当前官方文件已经是 2024 年发布的《山东工商学院普通全日制本科学生转专业管理办法》，其中明确废止旧的 2014 年试行规定。教务处也已经发布 2026 年转专业通知，包含具体报名日期、条件入口和办理流程。现有知识条目仍只有“按规定申请、关注通知”等概括内容，才会让模型只能给出入口式回答。

## 2. 当前问题与证据

### 2.1 知识内容不足且有过时表述

- `js/data.js` 的 `zhuanzhuanye` 条目只写了“具体按规定执行”，没有保存资格条件、禁止情形、时间和考核流程。
- 当前条目沿用了已经被新办法废止的旧规定名称。
- 2026 年官方通知实际给出了报名时间：2026 年 4 月 23 日至 4 月 27 日 14 时；当前知识库没有让回答使用这些信息。
- 2024 年现行管理办法详细列出了适用学生、正常与特殊情况、基本条件、不能申请的情形、报名、审核、笔试、面试、公示和审批流程。

### 2.2 采集入口覆盖不足

- 教务处来源已登记，但采集器默认从通用通知页开始，单次页数又有限，可能到不了“学籍管理”和“教学管理文件”的专门列表。
- 自动采集按安全规则不下载 PDF、Word 和 Excel 附件，因此现行管理办法需要人工核验后导入，不能依赖爬虫自动补全。
- 新抓取内容默认进入待审核状态；只有人工审核发布并重新生成向量后才能供 AI 使用。

### 2.3 检索会丢失长文件中的部分关键信息

- 当前语义检索按文档去重，同一份长文件最多保留一个命中切片。
- “什么时候申请、需要什么条件、要什么材料”是多意图问题，一个切片通常覆盖不全。
- 当前检索只允许仍在有效期内的资料，没有受控的“历史参考”路径。

### 2.4 页面把 Markdown 当普通文字显示

- `js/ai.js` 先对回答执行 HTML 转义，再只把换行替换成 `<br>`。
- 这种做法能防止脚本注入，但不会解析 Markdown，所以 `**加粗**`、列表等符号会原样显示。

### 2.5 当前接口不是流式输出

- Edge Function 等模型完整生成后才返回 JSON。
- 前端只能显示加载动画，直到完整回答到达。
- 当前 v25 完整响应中位数为 6.815 秒，P95 为 10.719 秒，可作为加入流式输出前的完整响应基线。

## 3. 推荐执行方案

### 阶段 A：建立回答质量基线

新增固定评测集，先记录当前 v25 的回答表现，再修改质量相关代码。

评测集建议使用 24 道公开校园问题：

- 6 道年度通知时间题；
- 6 道资格、限制条件题；
- 4 道材料和办理流程题；
- 4 道同时询问两个以上事项的多意图题；
- 2 道只有往年通知可参考的问题；
- 2 道资料确实不足、应当拒绝猜测的问题。

每道题保存人工编写的“必须回答点”和允许引用的来源，不把模型答案提交进 Git。报告只进入被忽略的 `out/ai-quality/`。

基线指标：

- 子问题覆盖率：问了几个问题，回答了几个；
- 直接回答率：有资料时是否仍只让用户“查看规定”；
- 事实有据率：每个事实是否能在引用资料中找到；
- 时效正确率：是否优先使用当前通知，是否把过期日期当成今年日期；
- 历史标注率：往年信息是否明确写出年份和“仅供参考”；
- 引用正确率：`[1]` 等编号是否对应实际资料；
- 无依据克制率：没有资料时是否明确说无法确认；
- 完整响应耗时、错误率，以及流式上线后的首段文字时间。

### 阶段 B：补齐官方知识并修正时效

1. 将转专业资料拆成两类独立文档：
   - 长期政策：2024 年《山东工商学院普通全日制本科学生转专业管理办法》；
   - 年度安排：2026 年转专业工作通知及经审核的学院实施方案摘要。
2. 更新或替换 `js/data.js` 中含旧规定名称的 `zhuanzhuanye` 条目，不能继续把旧规定显示为现行依据。
3. 新增经过人工核验的官方知识 JSON，使用稳定 slug、官方 URL、发布日期、核验时间和适当有效期。
4. 给资料增加元数据：
   - `topic_key`，例如 `major-transfer`；
   - `document_role`：`policy`、`annual_notice`、`guide`；
   - `notice_year`；
   - `allow_historical_reference`；
   - 可选的申请起止时间。
5. 给教务处来源增加明确的起始列表：学籍管理页和教学管理文件页。继续保留域名白名单、robots、限速、页数上限和人工审核。
6. 审核发布后重新生成 1024 维向量。

年度通知不应在报名结束后立即消失。建议保留到当年年底，并在上下文中标记“报名期已结束”。长期管理办法在被新文件替代前保持有效。

### 阶段 C：增加受控的历史参考检索

检索分两步：

1. 优先查找当前有效的政策和当前年度通知。
2. 只有找不到当前年度通知时，才查找同一 `topic_key` 下最近三年的已审核官方通知。

历史结果必须由服务端标为 `historical_reference`，上下文写明年份、失效状态和禁止事项。模型必须遵守：

- 先说“今年通知尚未收录或尚未发布”；
- 再说“以下为 2025 年通知，仅供时间和流程参考”；
- 不得把往年的具体日期、名额或学院要求说成今年安排；
- 当前政策与历史通知冲突时，以当前政策为准；
- 学生整理资料不能覆盖官方资料。

### 阶段 E：安全渲染 Markdown

推荐把固定版本的 Markdown 解析器和 HTML 清理器放进仓库，不依赖运行时 CDN，也不增加打包步骤。实现原则：

- Markdown 解析后必须再清理 HTML；
- 禁止原始 HTML、脚本、事件属性和 `javascript:` 链接；
- 只允许段落、加粗、标题、列表、引用、安全链接和行内代码等必要元素；
- 外部链接只允许 HTTP/HTTPS，并加 `rel="noopener"`；
- 为标题、列表、引用、代码和段落补移动端样式；
- “复制回答”复制可读纯文本，不复制页面标签；
- 增加恶意 Markdown、残缺 Markdown、超长列表和链接协议测试。

2026-09-19 实现与验收记录：

- 新增仓库内固定版本 `SafeMarkdown 1.0.0`，不依赖运行时 Markdown CDN 或构建步骤；
- 支持段落、标题、加粗、斜体、有序/无序列表、引用、安全链接、行内代码、代码块和分隔线；

### 阶段 F：加入流式输出

保持浏览器不能接触模型密钥，流式仍由 `campus-ai` 中转。前端通过 `fetch()` 读取 POST 响应流，不使用只能发送 GET 的 `EventSource`。

协议建议使用 `text/event-stream`：

- `meta`：来源、剩余额度、检索方式；
- `delta`：新增回答文字；
- `done`：完整耗时、模型状态和结束信息；
- `error`：流开始后的超时或上游错误。

服务端对百炼 Responses API 发送 `stream: true`，解析 `response.output_text.delta` 等事件，再转换为本站稳定事件格式。旧的非流式 JSON 路径暂时保留，作为兼容与回退路径。

前端累积文字并按约 80 毫秒节流，使用同一套安全 Markdown 渲染器刷新回答，避免每个字符都重排页面。用户取消、切换页面或网络断开时应中止上游请求。流式开始后失败时，保留已经显示的文字，并给出“回答中断，可重试”的状态。

流式后 `Server-Timing` 响应头无法记录完整模型耗时，因此完整阶段计时放进 `done` 事件。基准脚本同时记录：

- 首个响应头时间；
- 首段可见文字时间；
- 完整回答时间；
- 中断率和重试率。

M6 完成记录（2026-09-20）：`campus-ai` 新增可选的 `text/event-stream` 路径，向百炼 Responses API 或 Chat Completions 发送 `stream: true`，并统一转换为 `meta`、`delta`、`done`、`error` 四类事件。旧 JSON 路径保持不变。前端按约 80 毫秒节流刷新安全 Markdown，离开 AI 页面时中止请求；流开始后失败会保留已有文字并显示重试提示。完整分段计时随 `done` 返回，基准脚本新增 `--stream`、首段文字时间和中断率字段。

### 阶段 G：对话可用性补强

在核心四项完成后，建议增加两项低风险改进：

## 4. 验收标准

### 回答质量

- 固定评测集中，所有明确子问题都被回答，或逐项说明缺少哪项资料。
- 当前年度通知存在时，100% 优先使用当前通知。
- 使用往年通知时，100% 标出年份和“仅供参考”。
- 资料已包含细则时，不再出现只让用户查看规定的入口式回答。
- 关键事实引用正确，零条无来源政策断言。
- 转专业示例必须使用现行 2024 管理办法和 2026 通知，不得继续把 2014 试行规定当成现行依据。

### 页面与安全

- 页面不再显示裸露的 `**`、列表符号等 Markdown 控制字符。
- 恶意 HTML、事件属性和危险链接协议全部被过滤。
- 手机和桌面宽度下，长列表、链接、引用和流式光标不溢出。
- 屏幕阅读器能感知回答正在生成和生成完成，减少动态效果设置仍有效。

### 性能与稳定性

- 流式首段可见文字中位数目标不高于 3 秒。
- 完整回答中位数目标不高于 8.5 秒，P95 目标不高于 14 秒；若质量提升导致回答更长，需同时报告字数变化。
- 关键词降级、无命中、限额、超时、向量失败和模型失败继续正常工作。
- 不保存完整聊天正文，不在报告中写入密钥或设备标识。

## 5. 测试与发布顺序

1. 运行现有知识、导入、检索、向量传输和 AI 性能离线测试。
2. 新增当前通知优先、历史降级、多切片、Markdown 清理和流分片测试。
3. 用固定评测集建立修改前质量基线。
4. 只部署知识和检索改进，完成同题质量对照。
5. 再启用安全 Markdown，检查手机和桌面页面。
6. 最后开启流式输出，比较首段和完整响应耗时。
7. 保留当前 v25 作为回退版本；任何数据库写入、知识导入、部署和真实模型测试都在执行前取得明确授权。

## 6. 建议采用的范围

推荐完整执行阶段 A 至 F。阶段 G 的跟进按钮可以同时加入；两轮临时上下文可以在核心质量指标通过后再启用，避免一次变更多个回答变量。
